# 이음 — 개인 업무 실행 시스템

## 해결하려던 문제
메일·메신저·회의록·보고서에 업무가 흩어져 있어, 이미 결정한 일과 새로 해야 할 일을 다시 찾아 정리해야 한다. 요약 자료가 늘어나는 것만으로는 업무가 이어지지 않는다.

## 설계의 중심
자료 → 내 업무 판단 → 다음 행동 → 진행 상태 → 후속 근거의 순환을 만든다. 같은 업무에 자료가 추가되어도 업무 ID와 본인 메모·완료 상태를 유지한다. 사용자는 전체 정보를 다시 읽는 대신 오늘 이어갈 일을 확인한다.

## 두 가지 결과물
1. 실제 운영 중인 개인 업무 시스템: 발표자가 본인 환경의 수집·갱신·업무 관리 흐름을 시연한다. 이 패키지가 그 자동 수집 환경까지 포함한다고 설명하지 않는다.
2. 이음 스타터 패키지: 다른 사람이 별도 계정 설정 없이 자료 등록부터 진행 관리까지 실행하고, 개인 AI 도구에 규칙과 코드를 전달해 자기 환경으로 확장하는 제출용 실행본이다.

## 적용 기술과 의미
| 기술 | 구현 위치 | 업무에서의 의미 |
| --- | --- | --- |
| 문장 규칙 기반 후보 추출 | core.js candidates | AI 없이도 명시적인 할 일을 검토 대상으로 제시 |
| 구조화된 AI 결과 계약 | ieum.import v1 | 어떤 AI에서 분석해도 같은 형식으로 수용 |
| 업무 ID 기반 병합 | core.js merge | 후속 자료로 업무가 중복 생성되는 문제 완화 |
| 검토 후 저장 | 후보 편집 화면 | 불명확한 담당·기한을 사람이 결정 |
| 로컬 저장·백업·복원 | app.js | 새로고침 후 기록 유지 및 개인 데이터 이동 |
| 근거·변경 이력 | source_refs, history | 어떤 자료로 무엇이 바뀌었는지 확인 |
| AI 실행 지침 | AI_START.md | 설치와 운영 규칙을 다른 AI에게 전달 |

## 발표 흐름 (약 3분)
“업무가 없는 것이 아니라, 여러 자료에 흩어져 있습니다.”
1. 실제 업무 시스템에서 오늘의 업무와 다음 행동을 보여준다.
2. 제출본에서 예제 회의록을 넣고, 후보를 고른 뒤 업무로 저장한다.
3. 한 건에 메모를 남기고 완료한다. 기존 ID의 AI 결과 파일을 반영해 완료·메모와 새 근거가 함께 남는 것을 보여준다.
4. 달력·업무 이력과 보고 초안을 보여준다.
5. “수집 도구는 달라도 됩니다. 업무를 이어가는 규칙과 코드를 패키지로 제공합니다.”

## 검증과 한계
검증 기록은 VERIFICATION.md를 참조한다. 합성 자료 기반 기능 검증과 실사용 효과 측정을 구분한다. 후보 찾기는 LLM이 아니며 API를 호출하지 않는다. 자동 수집·예약 실행·로그인·다중 기기 동기화는 이 독립형 기본판에 포함하지 않는다. 비용 절감·생산성 향상 수치를 실측한 것으로 제시하지 않는다.
