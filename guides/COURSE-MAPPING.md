# 이음: 교재와 구현의 대응

기준일: 2026-11-21 / 과제용 v2.19.0

## 목적과 유지한 결정
자료를 요약해서 쌓는 것이 아니라, 흘러가는 대화·메일·회의록·보고서가 내 업무가 되고 계속 진행되게 한다. 실제 발표는 운영 업무보드로 한다. 과제용은 동일한 화면 구조와 업무 관리 기능을 유지하며 운영 데이터와 연결을 분리한다. 수집 도구는 다한닷 필수가 아니다. 개인 AI나 파일·폴더 입력을 사용할 수 있다.

## 첨부 최종 과제와 차이

- 주제·초기 개발·기능 고도화·반응형·테마·동적 데이터: 기존 구현을 유지하고 개선했다.
- `/be-ambitious`: Claude 전용 명령을 실행했다고 주장하지 않는다. 목적·완료 기준·제약을 먼저 정한 개발 지침으로 적용했다.
- 비공개 GitHub: 현 과제 저장소는 공개다. 비공개 요구와 정확히 일치하지 않는다. 임의로 공개 범위나 요금제를 바꾸지 않았다.
- Cloudflare: 현재는 GitHub Pages + Supabase다. 배포 개념은 대응하지만 Cloudflare Functions를 구현했다고 말하지 않는다.
- 인증: Supabase 이메일 인증 방식이다. Google OAuth 완료로 설명하지 않는다.
- AI API key: 브라우저·저장소에 넣지 않는다. 현재 ChatGPT Plus/Claude 개인 화면에서 분석하고 결과를 가져온다. 자동 모델 호출 기능은 없다.
- OneDrive: MSAL/Graph 연동 소스가 있으나 회사 앱 등록 정보가 필요하다. 파일·폴더 직접 가져오기는 별도 설정 없이 사용한다.
- OneNote: 직접 계정 연결은 구현하지 않았다. 내보낸 문서나 본문 입력을 활용한다.
- 테스트: 코드 및 PostgreSQL 권한 테스트를 수행한다. 성능 목표 수치나 직원 활용 효과는 실측 전이므로 달성했다고 발표하지 않는다.
- 발표 슬라이드·최종 녹화·제출: 다음 작업이다. 이 문서는 발표 스토리와 구현 증거를 정리한 것으로 최종 PPT를 대신하지 않는다.

## 발표 흐름 초안
1. 문제: 정보는 여러 곳에서 들어오지만, 내가 해야 할 일과 후속 확인은 흩어진다.
2. 자료: 특정 수집 앱에 종속되지 않도록 파일·폴더·본문과 외부 AI를 입력 경로로 분리했다.
3. 해석: 프로젝트 규칙과 세 역할의 검토 기준으로 근거·연속성·다음 행동을 정리한다.
4. 통제: 구조화된 결과를 검사하고 사람이 반영 대상을 확인한다.
5. 실행: 기존 업무·일정·대화 이력에 이어 붙이며 완료·메모를 유지한다.
6. 검증: 개인 공간의 접근 제어와 충돌 처리를 테스트하고 별도 과제 환경에 배포했다.
7. 확산: 전체 코드·설치 SQL·작업 규칙·검증 절차를 '이음 스타터 패키지'로 제공한다. AI가 파일 하나로 모든 외부 인증을 자동 완성하는 것은 아니다.
