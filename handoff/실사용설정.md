# 이음 2.16 실사용 설정 및 검증 범위

## 실제 사용자 흐름
1. 이메일 인증으로 로그인한다. 개인 업무/대화는 과제 전용 Supabase에 저장된다.
2. 내 자료 가져오기에서 PDF/DOCX/XLSX/PPTX/텍스트/ZIP 또는 폴더를 선택한다.
3. 파일 본문은 브라우저에서 추출한다. 성공 파일과 미처리 사유를 구분한다. 원본 파일 바이트를 서버에 저장하지 않는다.
4. 기존 업무·사이트 대화·본문을 포함한 분석 지침을 개인 AI에 전달한다. 사이트 내부 자동 LLM 호출은 아직 없으며 외부 AI 결과를 가져오는 방식이다.
5. 결과를 미리 보고 새 업무/기존 업무 연결을 선택하여 저장한다.
6. 대화 요청 처리에서 가장 오래된 미처리 요청을 상태/메모로 직접 반영하거나, 개인 AI의 구조화된 변경 제안을 확인 후 반영한다. 변경 버전 충돌은 서버에서 거부한다.

## 문서 지원
- PDF: 텍스트 레이어, 최대 200쪽. 스캔/OCR, 암호 문서는 미지원.
- DOCX/PPTX: 본문 텍스트. 이미지·도형·차트 내용은 분석하지 않음.
- XLSX: 셀 값과 저장된 수식 계산값. 수식 재계산은 하지 않음. 시트 번호와 셀 주소를 표시.
- TXT/MD/CSV/EML/JSON, ZIP 포함. HWP/구형 DOC/XLS/PPT는 변환 필요.
- 파일당 20MB, 배치 합계 50MB, 100개, 추출 본문 650KB 한도. 압축 해제 크기 제한 적용.
- 파일 파싱 실패를 성공으로 표시하지 않음. 추출 내용은 사용자가 확인해야 함.

## OneDrive 실제 연결
OneDrive 계정 연결 버튼은 모의 코드가 아닌 Microsoft MSAL + Graph로 구현했다. 실제 계정 시험에는 아래 앱 등록이 필수다.

회사 Microsoft Entra 앱 등록:
- 앱 이름 예: 이음 개인 업무보드
- 계정 범위: 회사 단일 테넌트 권장. 회사 Tenant ID 사용.
- 플랫폼: Single-page application (SPA)
- 정확한 Redirect URI: https://jinwoo165.github.io/assignment-workboard/microsoft-callback.html
- Microsoft Graph 위임 권한: Files.Read
- 클라이언트 비밀키 생성/입력 불필요. 비밀키를 프런트엔드에 넣지 않음.
- 회사 사용자 동의 정책에 따라 관리자의 승인이 필요할 수 있음.

설정 방법:
- 운영자가 VITE_MICROSOFT_CLIENT_ID, VITE_MICROSOFT_TENANT_ID를 설정하고 재빌드하면 직원별 앱 ID 입력이 필요 없다.
- 연결 시험은 사이트의 최초 연결 설정에 공개 Client ID/Tenant ID를 입력해 진행할 수도 있다. 공개 식별자만 해당 브라우저의 작업공간별 설정으로 저장한다.
- 토큰은 MSAL 메모리 캐시에만 보관하고 창을 닫을 때 지운다. 업무보드 DB에 Microsoft 토큰을 저장하지 않는다.
- 계정 로그인→폴더 탐색→파일 1~10개 선택→본문 읽기→메타데이터 저장→내 자료 가져오기에 본문 전달.
- 회사 OneDrive/SharePoint 파일만 이번 다운로드 범위. 개인 OneDrive·다른 공유 드라이브 탐색·정기 무인 수집은 별도.
- Files.Read 권한은 사용자의 파일을 읽을 수 있는 권한이며 선택한 폴더만으로 권한 자체가 제한되는 것은 아니다. 제품은 선택한 파일만 다운로드한다.

## 배포 현황과 미검증
- 정상 계정용 주소가 실사용 진입점이다. ?presentation=1은 별도 모의 시연으로 유지한다.
- 본문 추출, 요청 미리보기, 서버 저장 로직은 테스트한다.
- 실제 Microsoft 앱 ID가 제공되지 않아 회사 계정 OAuth/다운로드는 아직 실계정 검증하지 못했다.
- 사이트 내 자동 LLM 분석과 PDF OCR은 구현 완료로 표현하지 않는다.
