# 이음 — 발표용 배포 안내

## 목적
흘러가는 이메일·대화·회의록·보고서에서 내 업무를 발견하고, 다음 행동·기한·출처·변경 이력을 연결해 업무가 계속 진행되게 한다. 다한닷은 필수가 아니다. 직원은 개인 AI와 수집 도구를 선택한다.

## 접속 주소
- 실제 계정용: https://jinwoo165.github.io/assignment-workboard/
- 발표용 시나리오: https://jinwoo165.github.io/assignment-workboard/?presentation=1
- 소스 ZIP: https://github.com/jinwoo165/assignment-workboard/archive/refs/heads/main.zip

## 3분 발표 순서
1. 실제 운영 시연은 발표자의 기존 개인 업무보드로 진행한다. 과제용은 독립된 코드와 DB다.
2. 발표용 주소에서 ① 자료 모으기: 사이트 대화와 OneDrive 회의록/견적 파일이 들어오는 상황을 보여준다. OneDrive 자료 버튼으로 합성 파일 목록을 확인한다.
3. ② 내 업무로 정리: 견적 검토·회신 대기·주간보고 등 세 가지 업무 및 일정으로 연결한다.
4. 업무를 열어 근거와 다음 행동을 확인한다. 진행 상태·메모 관리에서 완료 및 개인 메모를 저장해 볼 수 있다(시연은 메모리 저장).
5. ③ 후속 자료 연결: 수정 견적이 도착하면 같은 업무에 근거가 누적된다. 완료/메모는 유지된다.
6. ④ 업무 보고: 현재 업무와 다음 행동을 한 번에 확인한다.
7. ①을 다시 누르거나 새로고침하면 시나리오가 초기화된다.

## 구현과 시연의 경계
| 항목 | 실제 계정용 | 발표용 |
|---|---|---|
| 이메일 인증, 개인 공간 | 실제 배포/사용자 로그인 확인 | 로그인 없는 합성 공간 |
| 대화 저장 | DB 저장 및 재조회 확인 | 메모리 저장 |
| 자료 가져오기 | 텍스트·JSON, 미리보기 후 DB 저장 | 동일 UI 체험 |
| 사이트 대화 분석 전달 | 기존 업무·대화·링크를 공통 지침에 포함 | 준비된 대화 및 분석 시나리오 |
| 개인 AI 분석 | 외부 AI에서 실행 후 결과 가져오기 | 준비된 결과를 단계별 표시 |
| 기존 업무 연결 | ID 기반 연결, 출처 병합, 완료·메모 보존 | 동일 원칙의 예시 |
| OneDrive | 기존 파일/폴더 URL 등록 및 바로가기 저장 | 파일 변경→업무 연결을 가정한 모의 흐름 |
| OneDrive 자동 조회/본문 분석 | Microsoft 앱 등록·권한 승인 등 미구성 | 실제 조회 없이 합성 데이터 표시 |
| 업무 상태·메모·보관·이력 | 실제 저장 | 메모리 변경 |
| 보고 | 기존 화면/업무 내역 활용 | 저장된 시연 업무 기반 미리보기 |

## 운영 준비 관련 남은 사항
현재 배포본을 전사 자동 수집 시스템으로 표현하지 않는다. 실제 직원 확산에는 회사 Microsoft 앱 등록, 계정별 권한 및 회사 보안 정책 확인, 실제 AI 분석 품질 검증이 필요하다. 개인 AI 구독 로그인만으로 사이트 안의 AI 자동 실행이 되지는 않는다.

## 배포 방식
GitHub Pages main 브랜치 /docs, 별도 과제 Supabase. npm ci → npm test → npm run test:database → npm run build → npm run check:isolation. .env.local의 과제 연결값을 사용하며 운영 환경값은 금지한다. docs 빌드 파일도 main에 함께 반영해야 한다.
